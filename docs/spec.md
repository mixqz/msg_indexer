# Email Archive Indexer — 기능 명세 v1

작성: 2026-09-30 · 상태: 확정(Stage 1) · 레퍼런스: 기존 "Email Archive Indexer" exe(소스 소실)

## 1. 목표와 범위

로컬 백업 폴더의 `.msg` / `.eml` 파일을 빠르게 목록화·검색·정리하고, 열려 있는 Outlook(classic)에서 메일을 자동 백업하는 **Windows 11용 경량 무설치 exe**.

| 항목 | 결정 |
|---|---|
| 대상 OS | Windows 11 (x64). 관리자 권한 불필요, 레지스트리·시스템 폴더 쓰기 없음 |
| 배포 | 단일 exe 1개(목표 10MB 이하). 팀원 배포, 코드 서명 없음 |
| 규모 | 사용자당 백업 폴더 1곳, 로컬 드라이브, 파일 1만 개 이내, 하위 폴더 3단계 이내 |
| UI 언어 | 한국어 |
| 제외 | 첨부파일 저장, 새 Outlook(Windows용 새 Outlook) 백업, 네트워크/클라우드 폴더 최적화 |

## 2. 기술 구성

| 구성 | 선택 | 이유 |
|---|---|---|
| 런타임 | .NET Framework 4.8 (Windows 11 기본 탑재) | 별도 설치 없이 실행, exe가 작음, Outlook COM 연동 안정 |
| 화면 | WinForms, 가상 목록(VirtualMode) | 가볍고 1만 행도 즉시 표시 |
| 핵심 라이브러리 | .NET Standard 2.0 별도 프로젝트 | Docker(Linux)에서 자동 테스트 가능 |
| msg 읽기 | MsgReader (MIT) | 순수 .NET, Outlook 없이 읽기 |
| eml 읽기 | MimeKit (MIT) | 표준 MIME 파서, 한글 인코딩 처리 |
| 캐시/검색 | 자체 압축 캐시 파일(GZip) + 메모리 검색 | 1만 건 규모는 메모리로 충분. SQLite는 별도 네이티브 DLL을 exe 밖으로 풀어야 해 보안 프로그램 차단 위험·검증 불가 (Stage 4에서 변경) |
| 미리보기 | 내장 WebBrowser 컨트롤 + 텍스트 보기 | 추가 설치·용량 없음 |
| Outlook 연동 | 실행 중인 Outlook COM (late binding) | Outlook 버전별 참조 DLL 불필요 |
| 단일 exe | 의존 DLL을 exe에 내장(Costura.Fody) | 파일 1개로 배포 |
| 빌드 | Mac의 Docker(.NET SDK 컨테이너) | Mac 본체에 설치 없음 |

## 3. 메일 정보 추출 규칙

| 필드 | msg | eml |
|---|---|---|
| 방향(받음/보냄) | ① 앱이 Outlook에서 백업한 파일은 원본 폴더 기록 ② 발신자 주소가 '내 주소' 목록에 있으면 보냄 ③ 그 외 받음 | 동일 |
| 기준 시각 | 받음: 수신 시각(PR_MESSAGE_DELIVERY_TIME), 보냄: 발신 시각(PR_CLIENT_SUBMIT_TIME). 없으면 다른 쪽 → 파일 수정시각 순으로 대체 | 받음: 최상단 `Received` 헤더 시각, 보냄: `Date`. 없으면 `Date` → 파일 수정시각 |
| 발신자 이름 | 헤더 표시 이름 그대로(부서 표기가 있으면 포함). 표시 이름이 없으면 이메일 주소 | 동일 |
| 제목 | 원문 그대로(RE:/FW:/(1) 등 접두어 유지). 없으면 `(제목 없음)` | 동일 |
| 첨부 여부 | 실제 첨부만. 본문 삽입 이미지(서명 로고 등, inline/CID)는 제외 | `Content-Disposition: attachment` 또는 CID 미참조 파트만 |
| 일정 종류 | 메시지 클래스: `IPM.Schedule.Meeting.Request`=초대, `.Resp.Pos`=수락, `.Resp.Neg`=거절, `.Resp.Tent`=미정, `.Canceled`=취소 | `text/calendar` METHOD: REQUEST=초대, CANCEL=취소, REPLY+PARTSTAT(ACCEPTED/DECLINED/TENTATIVE)=수락/거절/미정 |
| 그 외 | 수신자·참조, 본문 텍스트, 첨부파일명 목록, 메일 고유번호(Message-ID), 파일 크기 | 동일 |

- 시각은 모두 PC 현지 시간(KST)으로 변환한다.
- '내 주소' 목록은 Outlook 백업 때 계정 주소를 자동 등록하고, 설정에서 직접 추가할 수도 있다.
- 읽기에 실패한 파일은 앱을 멈추지 않고 `오류` 상태와 사유로 표시한다.
- 문자셋 표기가 없는 오래된 eml은 UTF-8을 먼저 시도하고, 안 되면 PC 지역 설정의 ANSI 코드 페이지(한국 949, 일본 932, 중국 간체 936, 서유럽 1252 등)로 읽는다.

## 4. 파일명 정규화 규칙

형식: `YYMMDD_HHMMSS_발신자_제목_첨부O|X.확장자`

예: `260823_175434_Alex Kim [Sales Team]_W35 team agenda_첨부X.msg`

| # | 규칙 | 처리 |
|---|---|---|
| 1 | 날짜·시간 | 3장의 기준 시각. `YYMMDD_HHMMSS` |
| 2 | 발신자 | 3장의 발신자 이름 원문 |
| 3 | 제목 | 전체 유지, 접두어 유지 |
| 4 | 첨부 | 실제 첨부 있으면 `첨부O`, 없으면 `첨부X` (화면 언어별 표기: en·es·fr `AttY`/`AttN`, ko `첨부O`/`첨부X`, ja `添付有`/`添付無`, zh `有附件`/`无附件`). 발신자·제목이 비면 언어별 `(no sender)`/`(no subject)` 등. 어느 언어 표기로 된 파일이든 '정규화됨'으로 인식해 언어를 바꿔도 다시 바꾸지 않는다 |
| 5 | 금지 문자 `\ / : * ? " < > \|` | 모양이 같은 전각 문자로 치환 (`/`→`／`, `:`→`：`, `?`→`？` …). 줄바꿈·탭은 공백 1칸, 연속 공백은 1칸 |
| 6 | 끝의 점·공백, 예약어(CON, NUL 등) | 제거하거나 뒤에 `_`를 붙임 |
| 7 | 경로 길이 | 전체 경로 259자 이하. 넘을 때만 제목 끝을 최소한으로 줄이고 `…`를 붙임. 전체 제목은 캐시에 보관해 목록·검색에는 온전히 표시 |
| 8 | 이름 충돌 | 다른 메일과 이름이 같으면 ` (2)`, ` (3)` … 을 붙임. 같은 메일이면 6장의 중복 규칙 적용 |
| 9 | 이미 규칙대로인 파일 | 건너뜀 |
| 10 | 실행 전 확인 | '변경 전 → 변경 후' 미리보기 표에서 확인한 뒤 실행. 실행 기록을 남겨 [되돌리기] 가능 |

## 5. 캐시와 증분 스캔

- 위치: `<백업폴더>\.emailindex\index.bin` (숨김 폴더, GZip 압축, 본문은 메일당 64K자까지 저장). 설정 파일: `%APPDATA%\EmailIndexer\settings.json`(백업 폴더 경로, 내 주소, 창 크기 등)
- 이동·이름변경 감지: 사라진 파일과 내용이 같은 새 파일은 '이동'으로 처리 (중복 아님, 자동 삭제 안 함)
- 휴지통에서 복원한 파일은 다시 자동 삭제하지 않음 (삭제한 파일 해시 기록)
- 파일 식별: 상대경로 + 크기 + 수정시각. 이 셋이 같으면 다시 읽지 않는다.
- 스캔 흐름: ① 폴더 목록만 빠르게 비교 → ② 새 파일·바뀐 파일만 읽기 → ③ 사라진 파일은 캐시에서 제거
- 앱 시작 시 캐시로 즉시 목록을 표시하고, 증분 스캔은 뒤에서 진행한다(진행률·취소 가능).
- 앱이 한 이름변경·이동은 캐시를 직접 갱신해 다시 읽지 않는다.
- [캐시 재구축] 버튼으로 전체를 다시 읽을 수 있다. 캐시가 손상되면 자동으로 재구축한다.
- 성능 목표(1만 건): 캐시로 시작하는 데 2초 이내, 변경 없을 때 증분 스캔 5초 이내, 첫 전체 스캔 3분 이내

## 6. 중복 판정과 처리

| 등급 | 판정 | 처리 |
|---|---|---|
| 동일 파일 | 파일 내용 해시(SHA-256) 일치 | 자동 휴지통 대상 |
| 동일 메일 | Message-ID 일치(msg↔eml 교차 포함). Message-ID가 없으면 발신 주소 + 발신 시각(초) + 제목 + 본문 해시 일치 | 자동 휴지통 대상 |
| 유사 메일 | 발신자·제목 같고 시각 차이 1분 이내, 내용은 다름 | `유사` 표시만 함 |

- **자동 휴지통:** 증분 스캔에서 새로 들어온 파일이 기존 파일과 동일 파일이거나 동일 메일이면 새 파일을 휴지통으로 보내고, 기존 파일을 남긴다. 알림과 기록을 남긴다. 새 파일끼리만 겹치는 경우(기존 원본 없음)는 표시만 한다.
- **첫 스캔(캐시 없음):** 어느 파일이 원본인지 알 수 없으므로 자동 삭제하지 않는다. `중복`으로 표시하고, [중복 정리] 버튼에서 미리보기 후 일괄 휴지통 처리한다.
  - 남길 파일의 우선순위: 정규화된 이름 > msg 형식 > 수정시각이 오래된 파일
- **Outlook 백업:** 이미 있는 메일은 저장하지 않고 건너뛴다.
- 모든 삭제는 Windows 휴지통으로 보내므로 복원할 수 있다. 기록은 `<백업폴더>\.emailindex\actions.log`에 남긴다.

## 7. 검색·필터·정렬

- **검색:** 입력창 1개, 입력 즉시 결과 표시(0.3초 지연). 대상은 제목, 발신자, 수신자·참조, 본문, 첨부파일명이다.
  - 대상 칩 [전체] [제목] [사람] [본문] [첨부명]으로 범위를 좁힐 수 있다.
  - 여러 단어는 AND로 검색하고, `"따옴표"`는 정확한 구문으로 검색한다. 결과에 검색어를 강조 표시한다.
- **필터 패널(좌측, 접기 가능):**
  - 기간: 빠른 선택(오늘, 7일, 30일, 올해) 또는 직접 지정
  - 방향: 받음, 보냄
  - 첨부: O, X
  - 일정: 없음, 초대, 수락, 거절, 미정, 취소
  - 상태: 중복, 유사, 오류, 미정규화
  - 형식: msg, eml
  - 하위 폴더 트리
  - 발신자 상위 목록(메일 수 순, 클릭하면 해당 발신자로 필터)
- 필터는 조합해서 쓸 수 있고, [필터 초기화] 버튼과 현재 적용 중인 필터 칩을 보여준다.
- **정렬:** 모든 열 머리글을 클릭해 오름차순/내림차순을 전환한다. 기본은 기준 시각 최신순이다.
- 상태줄에 `전체 N · 표시 N · 선택 N`을 표시한다.

## 8. 미리보기·열기

- 목록에서 더블클릭, Enter 키 또는 [보기] 버튼으로 미리보기 창을 연다.
- 미리보기 창 구성:
  - 머리부: 제목, 발신자, 수신자·참조, 일시, 첨부 목록(이름만)
  - 본문: [서식 보기]가 기본이고 [텍스트 보기]로 전환할 수 있다
  - 버튼: [본문 복사] [Outlook으로 열기] [폴더에서 보기] [◀ 이전 / 다음 ▶] [닫기]
- 서식 보기는 외부 이미지, 스크립트, 링크 자동 이동을 차단한다.
- 텍스트 보기에서는 보안 배너 표식 문구(예: `ZjQcmQRYFpfptBannerStart/End`)를 제거한다.
- 파일 열기: Ctrl+O 또는 [열기] 버튼. Windows 기본 연결 프로그램(Outlook)으로 연다.

## 9. 파일 관리

- **선택 이동:** 대상 폴더를 고르면 선택한 파일을 이동한다. 같은 이름이 있으면 4장 8번 규칙을 적용하고, 캐시를 즉시 갱신한다.
- **선택 삭제:** 확인 창을 띄운 뒤 휴지통으로 보낸다.
- 오른쪽 클릭 메뉴에 보기, 열기, 폴더에서 보기, 정규화, 이동, 삭제, 경로 복사를 넣는다.

## 10. Outlook(classic) 자동 백업

- **대상:** 프로필에 있는 각 메일 계정의 받은편지함과 보낸편지함. 하위 폴더는 제외하고, Outlook 원본은 유지한다.
- **저장 위치:** `<백업폴더>\` 바로 아래 (하위 폴더를 만들지 않음). 저장할 때 바로 4장 규칙의 파일명을 적용한다. 사용자가 하위 폴더로 옮겨도 스캔이 찾아낸다.
- **Outlook 자동 실행:** Outlook(classic)이 꺼져 있으면 `outlook.exe`를 실행하고 연결될 때까지 최대 2분 기다린다. classic 대신 새 Outlook이 열리면 전환 안내.
- **기간 선택:** 마지막 백업 이후(기본), 최근 N일, 전체
- **건너뛰기:** 캐시에 같은 Message-ID(없으면 Outlook EntryID)가 있으면 저장하지 않는다.
- **실행 전 점검과 안내:**
  - 새 Outlook만 실행 중 → "새 Outlook은 자동 백업을 지원하지 않습니다. classic으로 전환하세요"
  - 앱과 Outlook의 권한 수준이 다름(한쪽만 관리자로 실행) → 연결할 수 없으므로 둘 다 일반 권한으로 실행하라고 안내
- **저장 방식:** 항목별로 `SaveAs(경로, olMSGUnicode)`를 호출한다.
  - 저장 뒤 파일이 실제로 존재하고 크기가 0보다 큰지 확인해야 '성공'으로 센다.
  - 메일 외 항목(회의 요청 등)도 SaveAs가 되면 저장하고, 안 되면 사유를 기록한다.
- **진행 표시:** 폴더별 `확인 N / 저장 N / 건너뜀 N / 실패 N`과 실패 사유 목록을 보여준다(레퍼런스 앱의 "항상 0개" 문제 재발 방지).
  - Outlook이 멈추지 않도록 50건 단위로 처리하고, 취소할 수 있다.

## 12. 테스트 데이터

- 자동 테스트용 샘플은 직접 합성해 만든다: eml은 MimeKit, msg는 MsgKit(MIT).
  - 한글 제목·발신자, 금지 문자, 긴 제목, inline 이미지만 있는 메일, 실제 첨부, 일정 5종, 중복(msg↔eml), 깨진 파일을 포함한다.
- 실제 파일 검증(선택): 사용자가 개인정보가 없거나 공개해도 되는 msg/eml 몇십 개를 `samples/real/`에 넣는다. 특히 회의 수락·거절 응답과 첨부가 있는 msg가 필요하다. 이 폴더는 저장소에 올리지 않는다.

## 13. 수용 기준 요약

1. 관리자 권한이 없는 Windows 11에서 exe를 더블클릭하면 설치 없이 실행된다.
2. 1만 건 폴더를 재실행할 때 2초 안에 목록이 표시되고, 변경분만 스캔한다.
3. 3장·4장 규칙대로 메타데이터를 추출하고 파일명을 만들며, 되돌리기가 동작한다.
4. 새로 들어온 동일 메일은 자동으로 휴지통에 가고, 첫 스캔에서는 표시만 한다.
5. Outlook(classic)의 받은편지함·보낸편지함 백업에서 저장 개수가 0보다 크고, 실패하면 사유를 표시한다.
6. 서식 미리보기와 텍스트 미리보기, Outlook으로 열기, 이동, 삭제, 검색, 필터, 정렬이 모두 동작한다.
